# 自有综合创作平台开发总任务

版本：2026-09-13。性质：目标范围与待开发总账，不是完成报告。

## 1. 产品定位与边界

融光是现有代码、数据和运行能力底座，不是产品功能边界。建设可独立完成策划、剧本、资产、生图、视频、声音、剪辑、质检和交付的自有综合创作平台。支持单项工具使用，也支持短剧、动画、广告和短视频项目化生产。产品名称暂不更改，待品牌确认。

页面按新产品信息架构重做，不受旧页面排列限制；复用经过审计的认证、资产、任务队列、模型接入、生成和合成能力。新功能先寻找等价实现，再决定扩展或新增；不预设重建后端、不另建第二套 Runtime。

首版以本地部署、单团队、桌面创作为主，兼顾窄屏查看、审批和轻操作。多租户商业服务、原生移动应用、模型训练平台和第三方插件市场列入后续候选，不作为首版硬依赖。

不得因为本计划直接安装全部节点、下载全部模型、调用付费服务或删除旧数据。每项执行前明确需求、资源预算和回滚路径。已获授权的页面重做不等于允许破坏历史项目。

## 2. 页面信息架构（目标，不代表现有路由）

| 一级入口 | 二级页面 / 工作区 | 核心用户动作 |
|---|---|---|
| 工作台 | 最近项目、待办、任务进度、运行告警 | 继续创作、快速生成、处理失败 |
| 项目中心 | 项目概览、策划、剧本、分集、分场 | 建立目标、组织故事、管理版本 |
| 创作工作区 | 分镜、角色、场景、道具、对白 | 编辑镜头与引用，批量生成 |
| 图像工坊 | 文生图、参考生图、编辑、局部重绘、扩图、高清 | 独立生图、比较、保存为资产 |
| 视频工坊 | 图生视频、首尾帧、对白口型、动作能力、增强 | 选能力、设参数、生成与比较 |
| 声音工坊 | 配音、对白、音乐/音效、音频处理 | 试听、编辑、对齐和授权管理 |
| 剪辑交付 | 时间轴、字幕、音轨、预览、渲染、交付包 | 组装作品并按规格导出 |
| 资产中心 | 全局/项目资产、版本、引用、标签、回收站 | 检索、复用、追溯来源 |
| 生产中心 | 队列、运行详情、候选片、质检、修复、用量 | 监控、重试、审批和选片 |
| 知识与模板 | 知识搜索、配方、提示词、案例、模板 | 带来源调用、测试和复用 |
| 能力管理 | 模型、Provider、工作流、Profile、Runtime | 安装前检查、测试、发布、下线 |
| 平台设置 | 成员权限、存储、备份、密钥、审计、系统状态 | 管理安全和运行环境 |

普通用户按“我要做什么”选择能力；工作流节点、模型文件和运行参数放高级设置。所有模块共享资产选择器、媒体预览器、任务状态和项目上下文，不各建孤立素材库。

## 3. 状态和证据规则

下面所有条目均为 PLANNED（待审计目标），不意味着底座没有实现。审计后转换为 NOT_STARTED / PARTIAL / IMPLEMENTED / VERIFIED / SUPERSEDED / BLOCKED；BLOCKED 必须记录缺失依赖和解除条件。

IMPLEMENTED 表示代码存在且基本检查通过；VERIFIED 必须同时满足条目验收与适用的页面/API/真实运行检查。历史 PR-001～030 保留原编号与原始证据，通过映射关联本任务，不直接继承 VERIFIED。

每个执行任务必须记录：编号、目标、现有实现位置、复用决策、依赖、前后端/API/数据变更、验收步骤、自动测试、实际结果、证据路径、风险、回滚方式、负责人或接手者、下一步。预估工期在代码审计后给出，不以未经确认的人力承诺日期。

## 4. 综合开发任务分解

### A. 基线与产品定义（依赖：无）

- A01 仓库及历史改动审计：识别现有前后端、数据、生成链和运行目录；交付可复用/待修/新增清单，保护未提交修改。
- A02 全平台能力矩阵：逐项关联本任务、历史 PR、K001–K009、代码、页面和证据；验收无无主任务、无凭空完成状态。
- A03 用户流程和版本范围：定义独立生成、项目制作、审核交付三条路径；列出首版支持和明确不支持的操作。
- A04 基线回归与恢复演练：记录旧项目、媒体、队列和服务健康，完成备份及隔离恢复；新开发不得损坏旧项目。

### B. 页面重做与设计系统（依赖：A01–A03）

- B01 新导航和页面规格：为上述十二个入口定义路由映射、布局、主操作、数据来源和权限，形成可评审页面规格。
- B02 设计令牌和通用布局：统一排版、色彩、间距、明暗主题、面板和表单；沿用当前 AGENTS 约束，需变更时先明确更新规则，不各页自行改标准。
- B03 公共创作组件：资产选择器、图像/视频/音频播放器、候选对比、参数面板、任务进度和错误操作；在至少三个业务页面复用。
- B04 工作台与项目中心重做：真实最近项目、进行中任务、待处理事项和能力入口；不得用静态数字伪装产品状态。
- B05 编辑器体验：自动保存、保存失败提示、撤销/重做边界、未保存离开提醒、长列表与大素材加载。
- B06 可用性与旧路由迁移：键盘、焦点、无障碍标签、窄屏、空/加载/失败/无权限状态；旧链接明确映射，页面刷新可恢复上下文。

### C. 策划、剧本与分镜（依赖：A、B02–B03）

- C01 项目创作简报：类型、画幅、风格、目标时长、预算和交付要求；保存为版本化项目约束。
- C02 剧本导入和编辑：文本导入、分集分场、对白编辑、版本差异与人工纠错；AI解析不得覆盖已确认版本。
- C03 分镜工作台：表格/卡片视图、镜头排序、景别、机位、时长、动作、对白和引用；两种视图读写同一数据。
- C04 镜头约束及变更影响：绑定角色/场景/声音版本，变更后标出受影响镜头与产物；用户确认后才重生成。
- C05 剧情状态与快照：实现所需 StoryEvent、状态引用和快照能力或复用等价结构；能从指定版本追溯生产输入。

### D. 资产和一致性（依赖：A、B03）

- D01 统一媒体资产：上传、元信息、校验、缩略图、标签、检索、项目归属和去重；大文件失败可重试。
- D02 角色资产：身份、造型、表情、动作和声音分开版本管理；镜头绑定准确版本，不随最新编辑漂移。
- D03 场景、道具和风格资产：多视角参考、光照/风格说明、复用模板；项目间引用遵循权限。
- D04 Reference Pack：角色/场景参考组合与顺序、用途、来源和授权；生产记录能还原实际输入。
- D05 生命周期与引用追踪：归档、回收、依赖检查、受控清理；被历史运行引用的资产不能静默物理删除。

### E. 图像工坊（依赖：D、K01–K03、B03）

- E01 文生图/参考生图统一入口：明确模型能力和尺寸等参数，真实进度与失败原因，结果可存为资产。
- E02 编辑、局部重绘和扩图：编辑画布、遮罩、输入版本和前后对比；先接入已可用能力，其余显示不可用原因。
- E03 批量与一致性生图：角色设定图、场景参考、分镜首帧批次；固定种子/参考和完整参数可追溯。
- E04 图像增强与版本选择：高清、修复等按实际能力发布；保留原图，输出尺寸和质量可检查。
- E05 生图回归集：覆盖人物、场景、中文提示、参考约束与失败输入；技术通过与人工质量评价分开记录。

### F. 视频工坊（依赖：D、K、L01–L03、B03）

- F01 统一能力选择：接入现有 H3、WAN_I2V_STANDARD、WAN_FLF_STANDARD、WAN_INFINITETALK；不得把后台注册当页面完成。
- F02 能力参数契约：首帧/尾帧/音频/参考、时长、帧率、分辨率和种子；验证 duration 到帧数及模型限制。
- F03 多候选生产：复用 VideoTask(count=3)、现有队列/consumer 和 VideoItems，映射 Takes；支持预览、对比、选择。
- F04 运动和控制扩展：按审计结果选择运镜/动作/姿态等高价值能力；每种先独立验证再发布，不批量装节点。
- F05 视频增强：新高清工作流、必要的插帧/修复、音轨保留和画幅处理；原片不覆盖，实测尺寸、时长和同步。
- F06 真实工作流 Run Capsule：三条 WAN 各有实际输入、输出、耗时、工作流/模型/Runtime版本和错误记录；短 smoke 不替代正式规格验收。

### G. 声音与对白（依赖：D、K、B03）

- G01 配音编辑器：逐句文本、声音、速度和情绪能力、试听及版本；不支持的参数不能伪装可用。
- G02 对白时间管理：句段、停顿、字幕及音频时间对齐；修改对白明确标记口型/视频需要重做。
- G03 声音身份与授权：声音来源、授权范围和撤回处理；声音克隆必须有明确授权，不默认启用。
- G04 音频处理：裁切、音量、降噪、混音和淡入淡出按现有可用工具接入；记录采样率、声道、响度和削波检查。
- G05 音乐/音效资产：先支持导入、检索和授权追踪；生成型能力作为可选适配，费用与权利核实后接入。

### H. 剪辑与交付（依赖：D、F、G、L）

- H01 时间轴基础：镜头排序、裁切、时长和选中 Take，同一时间模型支撑预览与导出；避免重复维护两套编排。
- H02 音轨和字幕：对白/BGM/音效、字幕样式、安全区与字幕文件；导出结果与编辑预览一致。
- H03 转场和画幅：基础转场、封面、片头尾及目标画幅；首先提供有限可靠组合，不承诺完整专业剪辑软件能力。
- H04 合成复用：复用 VideoComposeService，补齐 Legacy/Mixed Compose、失败重试和版本固定测试。
- H05 交付包：成片、封面、字幕、制作参数、来源/授权摘要及校验清单；不同导出规格不覆盖旧版本。

### I. 导演与自动化（依赖：C、D、K、L）

- I01 Director 输入输出契约：从创作简报和分镜产生可编辑计划，不允许对话文字被直接当成已执行结果。
- I02 可解释能力路由：按输入、时长、质量、预算与可用性推荐 Profile；展示原因，支持用户指定，不静默换模型。
- I03 有界自动执行：分步确认、预算上限、超时、停止、审批和恢复；用户能看到将生成多少任务。
- I04 首帧/一致性门禁：区分技术检查与人工创意确认；未通过时明确阻止哪些下游任务。
- I05 修复计划：复用现有 Repair 能力，限定重试次数和范围；修复只影响失败或明确选中的步骤。

### J. 知识库与模板（依赖：A02、D）

- J01 K001–K009 历史清点：来源、版权、版本、重复项、遗漏项；保留来源，不以资料数量计进度。
- J02 Canonical 和 Alias：统一 ID、语义去重、SUPERSEDED 映射；不得因合并抹掉历史引用。
- J03 可执行配方：把高价值提示词/技巧映射到参数、约束和具体能力；以一组真实输入证明能够调用。
- J04 知识检索与引用：返回来源、适用条件和证据等级；没有证据时显示未知，不捏造本地验证。
- J05 创作模板：短剧、广告、短视频等模板包含资产要求、步骤、预算说明和可替换能力；不复制出另一套生产引擎。
- J06 外部优点吸收台账：逐项记录来源、采用/改造/不采用理由、许可、内部任务及对比结果；不把外部项目整体搬入当集成。

### K. 能力、工作流与 Runtime（依赖：A01、A04）

- K01 能力注册规范：统一模型、Provider、部署、WorkflowVersion、Profile、Runtime的现有或等价关系；固定版本引用。
- K02 修正发布验证：检查 bindings、依赖、模型、输入输出、标准化哈希；禁止直接改数据库通过标记绕过验证。
- K03 能力管理页面：健康检查、测试运行、发布、下线和依赖缺失提示；未通过能力不得出现在默认可用列表。
- K04 Runtime Capsule 与 RT01–RT04：先找原测试定义再执行，记录 GPU/驱动/CUDA/Python/PyTorch/ComfyUI/custom nodes/models/attention/FFmpeg/SoX；定义缺失则标明阻塞，不自行冒用测试编号。
- K05 国内模型获取与校验：仅列实际缺失依赖，验证最终下载链路、版本和校验值，避免把境外跳转称为国内下载；下载前检查容量和许可。
- K06 Provider适配：提交/查询/取消/错误/限流/计费约定，凭证脱敏；先接需要的提供方，不穷举接入。
- K07 旧能力退役：确认替代物真实可用、历史引用可解析后禁用旧配置；模型文件清理另列明确目标和可恢复方案。

### L. 生产中心、质检与成本（依赖：A、K）

- L01 运行总览及详情：Run/Step/Take、原始任务、日志摘要、输入输出、耗时和失败原因互相可跳转。
- L02 幂等与并发：重复请求不产生额外收费任务；并发选片、重复回调、状态竞争和重复摄取有测试。
- L03 恢复和取消：进程/Redis重启、Runtime断连、超时、孤儿任务、部分成功；不支持远端取消时如实显示结果。
- L04 QC工作台：可解码、尺寸、帧数、音频等自动检查；创意、口型和一致性人工评价单独记录，有拒绝和复审流程。
- L05 成本和资源：预计/实际/未知用量分开，任务级预算和上限、GPU队列及存储占用；免费本地运行也记录耗时。
- L06 生产证据：Run Capsule、选择历史、修复历史和成片来源可追溯；输出可复查而非仅有成功状态。

### M. 安全、运维与开放接口（依赖：A04；随各模块持续执行）

- M01 身份与项目权限：审计现有权限，补齐跨用户/跨项目访问检查；至少覆盖资产、生成、下载和删除。
- M02 密钥和审计：凭证不进前端/日志/证据，敏感操作有审计；导出与备份明确脱敏策略。
- M03 上传与执行安全：文件类型/大小/路径校验、外部URL访问限制、工作流输入和脚本执行隔离；知识内容不具有执行授权。
- M04 存储与备份恢复：明确代码、模型、数据库、媒体、队列和证据位置及容量；隔离恢复验证，不只证明备份文件存在。
- M05 可观测与升级：日志、健康、失败率和资源告警；数据库迁移验证、部署回滚和故障操作手册。
- M06 开放API和导入导出：稳定版本、权限、分页、幂等和必要回调；先服务内部复用，公开插件市场另行立项。
- M07 权利与交付约束：资产/声音/模型使用许可、人工确认和删除请求处理；政策或法律结论需实施时核实。

### N. 全平台验收与交接（依赖：对应功能完成）

- N01 自动测试分层：单元、接口、权限、数据库迁移、页面端到端；失败结果进入任务状态，不能跳过后标完成。
- N02 VERTICAL-SLICE-001：真实执行 StoryboardItem → ProductionRun/Step → Existing VideoTask(count=3) → Existing RedisTaskQueue/VideoGenerationConsumer → 3 VideoItems → 3 ProductionTakes → QC → selectedTakeId → Existing VideoComposeService；保存幂等、恢复、Legacy/Mixed证据。
- N03 Golden runner：有界执行现有 fixture，先确认 DRAMA-GOLD/P0原始标准；真实观看和检查，不把 fixture 文件当通过。
- N04 多创作路径验收：至少覆盖独立生图、参考编辑、图生视频、对白片段、高清处理、项目成片六条实际页面操作路径。
- N05 性能基线：在当前硬件测页面、任务吞吐、显存和存储；按实测约定目标，禁止承诺未经测量的速度。
- N06 接手与发布包：安装/启动/恢复、任务总账、代码/API地图、已知问题、示例和证据索引；另一开发者能复现一条完整路径。

## 6. 页面和功能完成定义

1. 入口可发现，普通用户能理解操作；参数由真实能力约束，不展示假功能。
2. 页面使用真实API，刷新后状态一致，成功/失败/取消/空状态都有处理。
3. 能实际生成/编辑/保存/复用对应产物，用户可以预览，不只有任务ID。
4. 输入、版本、权限、费用和产物来源可追溯；重大操作有确认和恢复策略。
5. 自动测试及人工验收均记录实际结果；技术通过与创意质量分离。
6. 不破坏历史项目；已发布数据库迁移不改写，旧配置退役有替代与引用检查。
7. 文档更新到当前状态，未完成项及明确下一步留给接手者。

## 7. 执行和交接规则

本文件是总范围基准；近期执行顺序仍记录在进行中的 handoff 计划。开始某个模块时，按 AGENTS 在 dev-docs/2-in-progress/ 建独立目录，包含 development-plan.md、progress-tracking.md、technical-debt.md；子任务使用本文件编号加后缀，例如 B03-01。

一项任务未提供实际证据，不得从计划直接改为 VERIFIED；文档交付不代表任何平台功能已实现。本轮只建立总任务与入口关联，不修改业务代码、数据、工作流或运行环境。

后续新增需求必须归入现有模块，说明依赖、验收和是否改变阶段范围；确需新增模块才新增编号，避免无限扩展任务书。
