# 技术债与已知限制

- **提交入口与选定流程未联动**：剧情提交目前是显式 API。直接写 `selectedTakeId`
  或走 Legacy 更新路径可以绕过提交门禁；是否由 `ProductionRunService.selectTake` 之后
  自动触发，属于 PR-024 的决策，本需求刻意不改那台已 VERIFIED 的状态机。
- **`predecessor_event_id` 未校验归属**：只当作更正链的记录字段，没有校验它是否属于
  同一项目、同一主体。要么补校验，要么在有人真正使用前删掉这个字段——当前它是可选且未被读取的。
- **折叠不做增量**：`state()` 每次都从事件全量重放，快照只用于固化与漂移校验。
  事件量大时需要改成"从最近快照 + 增量事件"折叠，届时快照才真正成为读路径的一部分。
- **`subject_key` 是自由文本**：没有项目内的主体词典或规范化，大小写、别名会把同一角色
  拆成两个主体。规范化应随 PR-023 的分集契约一起定义。
- **`OPEN_LOOP` 的关闭未配对**：`RESOLVED` 目前只是再追加一条，折叠端没有把开环与闭环配对，
  `facts` 同理没有去重。
- **并发提交没有显式锁**：同镜头并发依赖唯一索引 `uk_story_event_idempotency` 兜底，
  冲突会冒泡成 500 而不是返回既有事件。
- **只有单元测试**：`storyState` 缓存的驱逐正确性、控制器权限与 JSON 契约未做
  数据库级或 API 集成验证（本机 46379 无 Redis，`ProjectWorkspaceCacheTests` 同样无法执行）。
- **lint 不缓存**：提交事件会改变 lint 结论，但事件提交方不持有契约缓存键，
  跨缓存失效的复杂度高于省下的几次查询。将来要缓存，需与 `commitShot` 做联合驱逐。
- **契约键格式只在 lint 时解析**：`define` 仅校验 JSON 形状，写成不带 `TYPE:KEY` 的键
  会在 lint 时抛 400，而不是在保存时被拒绝。
- **节拍匹配是子串包含**：对中文可用，但同义词、别名、繁简差异会被判为缺失；
  需要主体与节拍词典后才能收紧。
- **契约没有历史版本表**：`revision` 只递增、不保留历史内容，无法回答"当时是按哪一版契约通过的 lint"。
  Golden harness 若要留证，需要额外保存契约快照或其哈希。
